# Audit: premise, plan, and work — 2026-09-11

A critical re-examination of everything produced since the design brief: the wayfinder
map ([#2](https://github.com/Syynth/map-editor/issues/2)) and its tickets, the decision
log, and the three build waves on the `restructure` branch. Requested by the project owner
after switching models, with the instruction to verify rather than restate.

Everything marked **verified** was checked directly in this audit, not taken from an agent
report. Everything else is judgement, and says so.

## Verdict

Execution quality is high. The reasoning inside the closed tickets is genuinely good —
measured, self-correcting, and honest about uncertainty. But the plan's direction
contradicts the design brief's own guidance, nobody flagged it, and three waves of work
have produced a lot of infrastructure and not one feature, not one editor test, and no
artist contact. The foundation is real. Whether it is the right foundation is the question
the brief told us to ask and the map never did.

---

## 1. The premise contradicts the brief, and was never reconciled

The brief's "Read this first", verbatim:

> Don't build general abstractions (plugin APIs, generic tool frameworks, extensible
> registries) until two or three concrete cases actually need them. Hardcode first,
> extract later.

> Build the smallest thing that lets us learn something, then stop and show it.

> When "streamlined and friendly" conflicts with "powerful and general," friendly wins.

The map delivered: an extensible feature-module registry (#9), a generic tool/stroke actor
framework (#11), a command layer with a declarative availability predicate DSL (#8), and a
twelve-package layout (#3), four of whose packages are for code that does not exist. Zero
features exist as modules. There is one consumer. `PLAN.md`, retired this week, said the
same as the brief: *"the tool layer is a switch statement on three tools, not a plugin
API, for the same reason."*

This is not a hidden error. The project owner drove it — "actors all the way up",
"extensible", "commands" — and gave a real reason: *agents operate more reliably against
explicit statecharts.* That is a legitimate **new premise**: if agents write most of the
code, agent-legibility is a first-class requirement, and abstractions that make agents
reliable may pay off before a second human consumer exists.

But it was never written down as superseding the brief. The decision log records "actors
all the way up" with a WHY that ends *"it's my default at this point."* The brief still
says hardcode first. Both documents are live. A future session reading the brief will
conclude the map over-built; one reading the map will conclude the brief is stale.

**Resolution:** ruled the same day — see `docs/decision-log.md`, *"The brief's 'hardcode first' guidance is superseded: the prototype is done and this is the foundation"*. The owner's reason leads: the guidance was written for the prototype phase, which is over.

## 2. The primary user has been absent from every session

The brief: *"The primary user is an artist, not a programmer."* Its one concrete
acceptance test — can an artist slot Kenney's Tiny Town into a template sheet within an
hour — is #17, open, never run. Pixel-art-in-perspective on real hardware (#16) has never
been checked with an artist looking. Prefabs and reuse — *"how does the artist think about
reuse?"* — is fog.

Every hour of planning went to architecture. The plan has no artist in the loop at any
point. This is the largest strategic gap in the work, and not one that more agent waves
can close.

## 3. Risk is concentrated in a stack that is bleeding-edge in every dimension at once

| | version | state |
|---|---|---|
| xstate | 6.0.0-alpha.53 | alpha; 53 releases in 12 weeks; undocumented double-execution already bit once |
| @xstate/react | 7.0.0-alpha.2 | alpha; the one dependency #15 admits is "genuinely unverified in use" |
| React | 19.3 | newest major |
| Vite | 8.3 | newest major, new oxc/Rolldown plugin |
| Vitest | 5.0 | newest major; `bench` moved |
| TypeScript | 6.0.3 | pinned *because* the linter cannot take 6.1 |
| ESLint | 10 | newest major |
| Mantine | 9.6 | newest major |

On a codebase with zero editor tests. Each decision was locally rational — #15 in
particular is well argued, measured, and names its fallback. The aggregate risk was never
assessed anywhere. #15's core argument — *"v5's dialect is deleted upstream, so writing v5
is writing removed code"* — is weaker than it reads: v5 is stable and supported, and that
upstream is mid-rewrite is a reason to wait, not to jump. The double-run footgun is direct
evidence the alpha's semantics are not settled.

**Recommendation:** re-evaluate #15's fallback trigger after the first real actor is
written, explicitly, rather than leaving it implicit.

## 4. An unasked question: does #13 make #22 unnecessary?

#13 decided one document actor owns `writer`; everyone else sends it patches. If no
feature actor's transition body has a `writer` reference, it cannot write the store
inline — the v6 double-run hazard is structurally unreachable from every actor but one.

#20's own taxonomy pushes each constraint to the cheapest bucket: *structural →
type-checked → … → lint; lint is the residue.* The `enq`-purity rule (#22) is one of only
two rules justifying the type-aware ESLint choice — and #13's answer may have made it
structural. That would leave the no-styles rule as the sole justification for pinning
TypeScript to 6.0.3. Nobody cross-checked #13 against #22.

**Recommendation:** do the cross-check before #22 is worked. It may close the ticket.

## 5. What was done well

The closed tickets are the strongest artifact this project has. They measure instead of
trusting: #15 read the shipped `.d.ts` rather than the changelog; #4 measured `input`
leaking to the inspector; #8 found the double-run by being bitten by it. They correct each
other: #13 corrected #3's read count (44 → 59); #20 corrected #3 on pnpm not enforcing
direction; #24 caught #20's "6.x" being one digit too loose. They record what was *not*
decided.

The build, **verified** in this audit:

- The app renders and edits after React 19, Vite 8, and every file moving: 60 fps, 5k
  tris, zero console errors; a sculpt click enabled Undo and changed the mesh.
- The gate is green **uncached**: 12 turbo tasks, 60 tests.
- Boundaries are real: `import 'three'` into `packages/document` fails with TS2307;
  inverting a workspace dependency fails the direction test, which also catches the cycle.
- Moves are byte-identical: git reports 100% rename similarity on the 778-line
  `viewport.ts`.
- The direction test has a completeness check, so a new package cannot be silently
  unchecked.

## 6. What is wrong in the build

- **Editor tests: still zero.** 60 tests now — 7 new, all infrastructure (5 direction, 2
  export-cli). The map's destination was *"iterate quickly and safely on app behavior."*
  Three waves added no behavior test. The stated goal has not moved.
- **The direction test pre-places three nonexistent packages** (`registry`,
  `viewport-contrib`, `editor-host`, marked `planned: true`). A hypothetical layout is
  baked into a test that will fight whoever designs those packages for real.
- **`@napi-rs/canvas`** — an unplanned native binary dependency in `export-cli`, added to
  satisfy "no WebGL context". Defensible; undecided.
- **`packages/ui` is not self-contained** — its primitives render against the app-owned
  485-line `styles.css`. Correctly deferred as a rewrite rather than a move; now real work.
- **Docs drifted.** `stack.md` still cites `core/store.ts`; `MAP-EDITOR-CONFIG.md` still
  says `npm` and that the pump is unusable because the restructure is not done.

## 7. Process failures, owned by the orchestrating session

- Gate checks before this audit were turbo cache replays reported as green. The uncached
  run is also green, but that was not known until this audit ran it.
- The pump skill's model-tier guidance (builds on a cheaper tier, review on the top tier)
  was ignored; every agent ran on the session model at high effort, including adversarial
  review of byte-identical file moves. ~3.8M subagent tokens across three waves.
- A reviewer's refusal to push was overridden, with a stated reason, setting a precedent.
- Chip prompts described a skill their recipients could not invoke
  (`disable-model-invocation`), and a session was wrongly characterised as sloppy for the
  resulting gap.
- Two confident wrong claims (`can()` as an availability primitive; build tickets for
  extensibility), both corrected by peer sessions.

## 8. Recommended order of work

1. Record the reconciliation decision (brief's "hardcode first" vs the map's premise).
2. Run #17 with an actual artist. It is the brief's only acceptance test.
3. Cross-check #13 against #22 before touching the lint rule.
4. Write the first editor behavior test before any more infrastructure.
5. Merge `restructure`; add CI immediately, because the only gate is local.
6. Strip `planned: true` from the direction test; fix the doc drift; decide
   `@napi-rs/canvas`.
