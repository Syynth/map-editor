What does a feature module register?

Throwaway prototype for ticket #9, under map #2. Not an implementation.

The question

A feature module is a self-contained unit — a tool, a panel, an overlay — that attaches through a declared API rather than reaching into other parts of the editor. The standing position on the map is that this is a constraint: boundaries must keep a feature module able to live outside the app, but no extension API ships in this effort. The caveat was that seeing a concrete proposal might change that.

So: three shapes, each writing the same two features — a Smooth Terrain tool and an Outliner panel. Your reaction decides whether extensibility graduates from constraint to deliverable, and which shape the package boundaries in #3 have to accommodate.

All three obey the map's standing constraints identically: declarations are static module-level data registered at import; handlers ride with actors; arguments are plain serialisable data addressing targets by stable id. So the runtime behaviour below is the same under all three. What differs is what the feature author writes, what the module is allowed to import, and whether a feature can be turned off. Those are the things to react to.
