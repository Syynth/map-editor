A project is a folder anchored on papercut.json
Two doors on the startup screen, as in brink. The app opens projects; a map is opened within its project, never on its own.
New Project…
You pick

A folder, a name and the texel density.

You get

papercut.json at the root, maps/ with one empty map, sheets/ with the placeholder sheet copied in.

Guarantee

The project opens on a map that already sculpts and paints. Nothing to configure before the first stroke.

Open… a papercut.json
You pick

The project file. The folder it sits in is the project; the shell grants that folder.

You get

The last map you had open, or the first in maps/. Sheets, terrain sets, materials and the camera rig come from the project.

Guarantee

Every map in the folder shares one material list and one resolution profile, so tiles line up across maps by construction.

One identity. A map carries no material list and no resolution of its own; those are the project's. So there is nothing a map could mean outside one, and no door for a loose file.
Nothing to migrate. No map has been made yet, so the project format starts fresh and the map format is defined as the project's.
